📌 Key GGN Standard Rules & Updates

  • DATE: Always populated with today's execution date formatted strictly as mm/DD/yyyy (e.g. 09/10/2026).
  • SVC (Service Center Name): Represents the Service Center Name. If there is no service center name data present, it is kept strictly empty (""). Numeric 10-digit Call IDs / ASC Job Numbers are never placed into SVC.
  • No. (Row Index): Sequential 1-based index (1, 2, 3...) functioning as the row sequence number (SR. NO.).
  • Service Order No. (Call ID): Guaranteed 10-digit Call ID starting with 4******* (e.g. 4441809308), extracted from Management Lite or Print Command, with fallback to ASC Job No (ASC_JOB_NO). Never blank when Call ID data is present.
  • Reason (GSPN): Strictly populated from Management Lite row 2. It will never be overwritten by Step 1 Print Command's remarks.
  • REDO: 28th column located at the end of the template, populated from Management Lite row 1 (e.g. Y or N).
  • Enforced Blank Fields: Remarks, Sub Remarks, Pending At, and Pending Reason are strictly blank ("").

Open Pending RAW Formulations, Key-Based Schema & Extensible Column Registry

Modular context architecture powering Multi-Source GSPN input parsing, key-based column mapping, and dynamic column registrations.

Key-Based Schema
⚡ Multi-Source Auto Detection

Automatically distinguishes between different GSPN formats shown in Image 2:

  • Service Order Management Light: 14 top cols (with Assigned Time) & 9 bottom cols (with App Time, REDO, Risk Sensing).
  • Service Order Management (Bulk): 9 top cols (Model directly after Assigned, no Time cols) & 9 bottom cols.
  • Single-Line TSV / Excel: Full 25-col or 28-col flattened rows.
🔑 Key-Based Schema Mapping

Matches values using standardized semantic keys and alias dictionaries instead of brittle fixed index offsets:

service_order_no → ['SO NO', 'ORDER NO', 'CALL ID']
created_date → ['CREATED', 'REQUEST DATE']
model → ['MODEL', 'MODEL NO', 'MODEL CODE']
city → ['CITY', 'LOCATION', 'DISTRICT']
🧪 Authoritative Formulations

Centralized mathematical & string normalization rules:

  • SO Trimming: Strips trailing Edit, View, whitespace, and extracts 10-digit SO.
  • Date Parsing: Enforces DD.MM.YYYY; discards dummy 00.00.0000 or 00:00:00.
  • Aging & TAT: calcAging() and 6 TAT buckets (0-2d, 3-7d, 8-10d, 11-14d, 15-30d, 30+d).
// Example: How to add a new custom calculated column via OpenPendingContext API
window.OpenPendingContext.registerColumn({
  key: 'sla_status',
  header: 'SLA Status',
  width: 14,
  align: 'center',
  formula: (r) => (r.aging > 7 ? 'BREACHED' : 'ON-TIME')
});
